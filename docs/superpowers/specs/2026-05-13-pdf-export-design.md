# PDF Export for a Session — Design

**Date:** 2026-05-13
**Author:** Padmanabha Das (with Claude)
**Status:** Proposed

## Goal

Add a backend endpoint that generates a PDF for a single session, capturing the conversation between the user and the assistant. The frontend will trigger this with a button (out of scope for this spec).

## Non-goals

- Multi-session PDFs.
- Server-side caching of generated PDFs.
- R2 backups of generated PDFs.
- Inline image embedding in the PDF body.
- Message-count / size limits (deferred — single PDF for v1).

## Endpoint

`GET /api/v1/sessions/:sessionId/pdf`

### Path params

- `sessionId` — Claude session UUID (the JSONL filename UUID).

### Query params (all optional)

| Param             | Type    | Default | Behavior                                                                               |
|-------------------|---------|---------|----------------------------------------------------------------------------------------|
| `includeThinking` | boolean | `false` | If `true`, includes assistant `thinking` blocks in the rendered PDF.                   |
| `includeTools`    | boolean | `false` | If `true`, includes assistant `tool_use` and `tool_result` blocks in the rendered PDF. |

Parsing: a query value is `true` only when it equals the string `"true"` (case-insensitive). Any other value (including missing) is treated as `false`.

When both flags are false (default), the PDF contains user messages and assistant `text` blocks only — the cleanest chat-only view.

### Response

- **200** — `Content-Type: application/pdf`, `Content-Disposition: attachment; filename="<computed-filename>.pdf"`, PDF bytes in the body.
- **400** — invalid `sessionId` (missing/empty).
- **404** — no session found in MongoDB with that `sessionId`.
- **500** — generation failed (Puppeteer launch, render, or buffer error).

Error responses use the standard `ApiResponse` JSON shape, matching the rest of the API.

### Filename rule

- `slug` — slugified session title (`[^a-zA-Z0-9]+` collapsed to `-`, lowercased, leading/trailing dashes trimmed, max 60 chars).
- `sessionShort` — first 8 characters of `sessionId`.
- Final: `claude-lens-<slug>-<sessionShort>.pdf`.
- Example: `claude-lens-debugging-the-r2-upload-loop-a1b2c3d4.pdf`.

If the slug ends up empty (title is purely non-alphanumeric or missing), fall back to `claude-lens-session-<sessionShort>.pdf`.

## PDF content

### Cover header (top of page 1)

- **Session title** (large, bold).
- **Description** (if present).
- **Metadata strip** (two-column key/value):
  - Model (`session.aiModel`)
  - Project (basename of `session.rawProjectDir`)
  - Git branch (`session.gitBranch`, if any)
  - Source (`session.source` — `terminal` | `webui`)
  - Created at (formatted in machine timezone)
  - Total messages count
  - Generated at (machine local time + IANA TZ label)

### Body

Render each message in chronological order (`MessageModel.find({sessionInternalId}).sort({timestamp: 1})`).

For each message:

**User message** (`content` is `string`)

- Label: `You` + small timestamp (`HH:mm:ss <TZ>`).
- Markdown-rendered body.
- Attachments listed below the text — see "Attachments".

**Assistant message** (`content` is `ContentBlock[]`)

Render each block in array order:

- `text` — markdown-rendered.
- `thinking` — only if `includeThinking=true`. Italic, dimmer color, prefixed `Thinking:`.
- `tool_use` — only if `includeTools=true`. Compact card: tool name (badge), `id` (small), input JSON in monospace block.
- `tool_result` — only if `includeTools=true`. Compact card showing matching `tool_use_id`, `is_error` indicator, full content rendered in monospace (no truncation).

Token usage (if `tokenUsage` present on assistant) renders as a small footer line under the message: `input X — output Y`.

### Attachments

All attachments are rendered as filename badges with mime type — no inline embedding in the PDF. Format: `[filename.ext] — [mime/type]`. If the attachment has an R2 URL, the filename text is a hyperlink to that URL. Same treatment for images, PDFs, and any other types.

### Page break / overflow

Natural HTML page breaks — no fixed boundary per message. Long messages flow across pages. CSS adds `page-break-inside: avoid` only on very small structures (e.g., the metadata strip).

### Page format

- Size: **A4**, margins **20mm** all sides.
- Body font: system sans-serif. Code: `ui-monospace`.
- Header on every page: session title (left), `page X / Y` (right). Small font, faded color.
- Footer on every page: `Generated by Claude Lens — <date> <time> <TZ>`. Small font, faded.

### Markdown

Rendered with `marked`. Code blocks use `highlight.js` for syntax highlighting (auto-detect language; fallback to plain monospace when detection fails).

## Implementation approach

1. **Library**: `puppeteer` (default cache dir `~/.cache/puppeteer/`).
2. **Render path**: build a single HTML string → `puppeteer.launch()` → new page → `page.setContent(html, { waitUntil: 'networkidle0' })` → `page.pdf({ format: 'A4', margin, displayHeaderFooter: true, headerTemplate, footerTemplate })` → stream the resulting Buffer to the HTTP response.
3. **Concurrency**: one Puppeteer launch per request (fresh). No browser pool for v1; revisit if usage grows.
4. **Timezone**: `Intl.DateTimeFormat().resolvedOptions().timeZone` for IANA TZ; falls back to `"UTC"` if empty.

## Data sources

- `SessionModel.findOne({ sessionId })` — session metadata.
- `MessageModel.find({ sessionInternalId: session._id }).sort({ timestamp: 1 })` — ordered messages.
- No R2 fetches.
- No JSONL reads.

## Error handling

| Case                                       | Status | errorCode                      |
|--------------------------------------------|--------|--------------------------------|
| Missing / empty `sessionId`                | 400    | `invalid_sessionId`            |
| Session not found in MongoDB               | 404    | `not_found_session`            |
| Puppeteer launch / render / buffer failure | 500    | `failure_pdf_generation`       |
| Failure after headers already sent         | —      | `res.destroy()` (no JSON body) |

## Out of scope (possible future improvements)

- Embedding images inline in the PDF body.
- R2 cache of generated PDFs.
- Multi-session PDFs (ZIP of PDFs).
- Chunking for huge sessions.
- Browser pool for higher throughput.
- Frontend button (separate task).
